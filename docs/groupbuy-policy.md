# glo 공동구매·협찬 운영 정책

> 최종 수정: 2026-08-10 (v2) · 도입 [#243](https://github.com/weglow-glo/glo-us/pull/243) → 개선 [#245](https://github.com/weglow-glo/glo-us/pull/245)·[#246](https://github.com/weglow-glo/glo-us/pull/246)·[#247](https://github.com/weglow-glo/glo-us/pull/247)·[#248](https://github.com/weglow-glo/glo-us/pull/248) · 포인트 규칙은 [points-policy.md](points-policy.md) 참조

## 1. 개요

셀러(인플루언서)에게 **영구 전용 링크**를 발급하고, 그 링크로 발생한 매출만 **회차(round) 단위로 분리 집계**해, **회차 종료 3주 뒤 금요일**에 매출 대비 수수료율로 정산하는 판매 채널.

- 회사가 **전액 수납** 후 수수료를 지급한다 — 셀러가 결제를 받는 구조가 아님.
- 재고·발주(WMS)·배송·CS는 일반 주문과 완전히 동일한 흐름.
- 구매자는 자사몰 카카오 회원으로 가입된다 — 회원 DB는 우리 자산.
- 고객 노출 문구는 **"○○님 × glo 프로모션 최대 혜택가"** — "공구/공동구매" 단어는 고객 화면에 쓰지 않는다.

## 2. 구조 (문 3개, 열쇠 각자)

| 화면 | 대상 | 접근 |
|---|---|---|
| `/product/@핸들` | 고객 (팔로워) | 링크 아는 사람만 — noindex, 사이트 내 링크 없음 |
| `/admin/sellers` | 운영자 | 기존 어드민 Basic Auth. 지원 심사·일정 승인·정산이 전부 여기 |
| `/seller` | 셀러 지망·셀러 | 카카오 로그인 — 권한 없으면 지원 폼, 있으면 대시보드 |

회원관리(`/admin/members`)는 **표시 전용**: "권한" 컬럼에 셀러/고객 상태만 보이고, 승격·해제 버튼은 없다.

## 3. 셀러 온보딩 — 지원 → 심사

1. 셀러 희망자가 사이트에 **카카오 로그인** 후 `glo-us.com/seller` 에서 지원서 제출 (활동명 · 연락처 · 채널 링크 · 팔로워 규모 · 소개).
2. 제출 후 `/seller` 는 "심사 진행 중" 화면 — 결과는 문자로 안내됨을 고지.
3. 운영자가 어드민 **셀러 지원 심사** 인박스에서 승인/반려.
   - **승인** → sellers 생성 + 카카오 계정 자동 연결 + 안내 발송 → 그 계정으로 셀러 센터 오픈.
   - **반려** → 사유 기록 + 발송. 셀러는 사유를 보고 **재지원 가능** (심사 대기는 계정당 1건).
4. 권한 해제는 셀러 테이블의 **활성/비활성 토글** — 즉시 포털 차단, 이력·정산 기록은 보존.

## 4. 전용 URL(핸들) — 셀러당 하나, 영구 고정

- `glo-us.com/product/@ellie` — **회차가 바뀌어도 링크는 동일.** 같은 링크가 "지금 진행 중인 회차"에 자동 연결되고(겹치면 늦게 시작한 회차 우선), 진행 중 회차가 없으면 일반 상세페이지로 리다이렉트.
- 핸들 지정은 **첫 회차 승인 때 한 번만** (영문 소문자·숫자·하이픈). 이후 회차 승인 폼에는 고정 URL이 읽기전용으로 표시. 수정은 셀러 테이블에서.

## 5. 회차(round) — 신청 → 승인, 차수 자동

- 매출 귀속·정산의 단위는 **회차**. 경로는 하나: **셀러가 포털에서 신청 → 운영자가 승인** (운영자 직접 생성 없음).
- 신청·승인 모두 **시각 단위**(datetime): "저녁 8시 오픈" 운영 가능. 시작 전엔 링크가 일반 페이지로, 종료 시각 이후엔 결제가 서버에서 거절 — 수동 개폐 없음.
- 승인 시 운영자가 정한다: **기간(일시) · 수수료율(%) · 전용 단가표** (표준 공구가 1/2/3/5/8/10/12개월이 기본값, 회차별 수정 가능). 전용 단가는 일반 판매가·런칭 이벤트와 완전 독립.
- **차수(1차, 2차…)는 승인 시 자동 부여** — 어드민·셀러 포털·정산 내역에만 표시, 고객 화면 미노출.
- 승인/반려 시 셀러에게 자동 안내 발송 — 확정 안내에는 전용 링크·기간·수수료율 포함.

## 6. 주문 귀속·가격 검증

- **그 링크에서 시작한 체크아웃만** 회차에 귀속된다 (쿠키 기반 기여 없음 — 오귀속 분쟁 방지).
- 가격은 서버가 "핸들 → 활성 셀러 → 진행 중 회차 → 전용 단가표" 경로로만 계산. URL 조작으로 혜택가 결제 불가.
- 프로모션 주문은 **포인트 적립·사용 모두 불가**. 리뷰 작성 포인트만 일반과 동일하게 지급 ([points-policy.md](points-policy.md)).
- 배송·교환·환불·배송지 셀프 변경은 일반 주문과 동일.

## 7. 정산 — 회차 종료 3주 뒤 금요일

- **기준일 = 종료 + 21일이 지난 뒤 도래하는 첫 금요일** (21일째가 금요일이면 그날). 정산 이체가 항상 금요일 하루에 모인다.
  - 예: 월요일 종료 → 3주 뒤 월요일 → 그 주 금요일 / 금요일 종료 → 3주 뒤 금요일 당일.
- 기준일에 운영자가 어드민에서 **정산 확정** → 그 시점의 결제완료(paid) 매출 스냅샷 × 수수료율이 확정 금액으로 박제.
  - 취소·환불은 paid에서 이미 빠져 있으므로 자동 차감. 교환은 매출 불변이라 무관.
- 확정 금액은 셀러 포털에도 동일하게 표시 — 근거 숫자가 하나라 분쟁 여지 없음.
- **기준일 이후 발생한 환불**은 차기 회차 정산에서 차감. 차기 회차가 없으면 별도 정산.
- 지급 방식(원천징수 3.3% vs 세금계산서)은 셀러 유형에 따라 다름 — 세무 확인 후 표준화 (TODO).

### 셀러 계약서 필수 4항목
수수료율 · 정산 시점(종료 3주 뒤 금요일) · 지연 환불 차감 · 콘텐츠 가이드

## 8. 자동 안내 (문자 → 알림톡)

셀러 심사 승인/반려, 일정 확정/반려 시 자동 발송. 문구는 `web/src/lib/groupbuy-notices.ts` 단일 소스.

- 현재는 **문자(LMS)** — 템플릿 등록 없이 바로 동작.
- SOLAPI 콘솔에서 알림톡 템플릿을 등록하고 Vercel 환경변수를 채우면 **자동으로 알림톡 전환** (실패 시 문자 대체발송):
  `SOLAPI_TEMPLATE_SELLER_APPROVED` · `SOLAPI_TEMPLATE_SELLER_REJECTED` · `SOLAPI_TEMPLATE_ROUND_APPROVED` · `SOLAPI_TEMPLATE_ROUND_REJECTED`
- 연락처가 없으면 발송 생략(로그만) — 지원서 경로는 연락처를 필수로 받으므로 항상 발송된다.

## 9. 운영 루틴 (회차 하나 기준)

| 시점 | 할 일 |
|---|---|
| 심사 (셀러당 1회) | 지원 인박스에서 채널 확인 → 승인 (자동 안내 발송) |
| 회차 시작 전 (5분) | 일정 신청 승인 — 기간(일시)·수수료율·단가 입력, 첫 회차면 핸들 지정 → 확정 안내 자동 발송 |
| 진행 중 | 없음 — 발주·배송·CS 전부 기존 자동 흐름. 매출 문의는 포털 안내 |
| 종료 후 (금요일 5분) | 기준일(금)에 어드민 **정산 확정** 클릭 → 확정 금액 계좌 이체 |

- 첫 회차는 소액 실결제 1건으로 귀속·대시보드 반영을 확인한 뒤 본격 홍보 권장.

## 10. 데이터·보안

- 스키마: `sellers`(핸들·계좌), `seller_applications`(지원서), `groupbuy_rounds`(차수·조건), `orders.round_id/seller_handle` — 마이그레이션 0012~0014.
- 계좌·연락처·지원서는 service_role 전용. 익명에는 활성 셀러의 id/핸들과 승인된 회차의 공개 필드만 열림 — 수수료율·정산액·메모는 컬럼 권한으로 차단.
- 셀러 포털은 자기 회차만 조회. 주문자 이름은 마스킹(김*연), 주소·연락처는 미노출.
- 트래킹(Meta/네이버)은 일반 구매와 동일하게 발화 — 회차 구분값 추가는 후속 (§11).
