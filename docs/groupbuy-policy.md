# glo 공동구매·협찬 운영 정책

> 최종 수정: 2026-08-10 · 도입 PR [#243](https://github.com/weglow-glo/glo-us/pull/243) · 포인트 규칙은 [points-policy.md](points-policy.md) 참조

## 1. 개요

셀러(인플루언서)에게 전용 구매 링크를 발급하고, 그 링크로 발생한 매출만 **회차(round) 단위로 분리 집계**해, 회차 종료 후 **매출 대비 수수료율**로 정산하는 판매 채널.

- 회사가 **전액 수납** 후 수수료를 지급한다 — 셀러가 결제를 받는 구조가 아님.
- 재고·발주(WMS)·배송·CS는 일반 주문과 완전히 동일한 흐름.
- 구매자는 자사몰 카카오 회원으로 가입된다 — 회원 DB는 우리 자산.
- 고객 노출 문구는 **"○○님 × glo 프로모션 최대 혜택가"** — "공구/공동구매" 단어는 고객 화면에 쓰지 않는다.

## 2. 구조 (문 3개, 열쇠 각자)

| 화면 | 대상 | 접근 |
|---|---|---|
| `/product/@핸들` | 고객 (팔로워) | 링크 아는 사람만 — noindex, 사이트 내 링크 없음 |
| `/admin/members` · `/admin/sellers` | 운영자 | 기존 어드민 Basic Auth |
| `/seller` | 셀러 | 카카오 로그인 + 운영자가 권한 부여한 계정만 |

## 3. 회차(round) 규칙

- 매출 귀속·정산의 단위는 셀러가 아니라 **회차**다. 한 셀러가 여러 회차를 반복 진행할 수 있다.
- 유형: `groupbuy`(셀러 신청 → 운영자 승인) / `sponsored`(협찬 — 운영자 직접 개설, 즉시 승인).
- 회차마다 운영자가 정한다: **판매 기간 · 수수료율(%) · 전용 단가표**.
  - 표준 공구 단가표(1/2/3/5/8/10/12개월)가 기본값으로 채워지며 회차별 수정 가능.
  - 전용 단가는 일반 판매가(런칭 이벤트 포함)와 완전히 독립 — 이벤트 마감의 영향을 받지 않는다.
- 기간 효력은 자동: 시작 전엔 링크가 `/product`로 리다이렉트, 종료 후엔 결제가 서버에서 거절된다. 수동 개폐 없음.
- 핸들(URL)은 승인 시 발급. 추측 어려운 조합 권장 (예: `ellie-oct`).

## 4. 주문 귀속·가격 검증

- **그 링크에서 시작한 체크아웃만** 회차에 귀속된다 (쿠키 기반 기여 없음 — 오귀속 분쟁 방지).
- 가격은 서버가 회차 단가표에서만 계산한다. URL 파라미터 조작으로 혜택가 결제 불가.
- 미승인·기간 외 회차의 주문 시도는 서버가 거절한다.
- 프로모션 주문은 **포인트 적립·사용 모두 불가**. 리뷰 작성 포인트만 일반과 동일하게 지급된다 ([points-policy.md](points-policy.md)).
- 배송·교환·환불·배송지 셀프 변경은 일반 주문과 동일.

## 5. 정산

- **기준일 = 회차 종료 + 21일.** 취소·교환·환불이 정리될 시간을 둔다 (청약철회 7일 + 여유).
- 기준일에 운영자가 어드민에서 **정산 확정** → 그 시점의 결제완료(paid) 매출 스냅샷 × 수수료율이 확정 금액으로 박제된다.
  - 취소·환불은 paid에서 이미 빠져 있으므로 자동 차감 — 별도 계산 없음.
  - 교환은 매출 불변이라 정산에 영향 없음.
- 확정 금액은 셀러 포털에도 동일하게 표시된다 — 근거 숫자가 하나라 분쟁 여지 없음.
- **기준일 이후 발생한 환불**은 차기 회차 정산에서 차감한다. 차기 회차가 없으면 별도 정산.
- 지급 방식(원천징수 3.3% vs 세금계산서)은 셀러 유형에 따라 다름 — 세무 확인 후 표준화 (TODO).

## 6. 운영 루틴 (회차 하나 기준)

| 시점 | 할 일 |
|---|---|
| 시작 전 (10분) | ① 셀러가 사이트 카카오 가입 → `/admin/members`에서 **[셀러 권한 부여]** ② `/admin/sellers`에서 신청 승인 또는 회차 직접 생성 (기간·수수료율·단가) ③ 발급된 링크를 셀러에게 전달 |
| 진행 중 | 없음 — 발주·배송·CS 전부 기존 자동 흐름. 매출 문의는 포털 안내 |
| 종료 후 (5분) | 기준일에 어드민 **[정산 확정]** 클릭 → 확정 금액 계좌 이체 |

- 권한 해제는 회원관리에서 [해제] — 포털 접근 즉시 차단, 회차·정산 이력은 보존.
- 첫 회차는 소액 실결제 1건으로 귀속·대시보드 반영을 확인한 뒤 본격 홍보 권장.

## 7. 데이터·보안

- 스키마: `sellers`, `groupbuy_rounds`, `orders.round_id/seller_handle` (`web/supabase/migrations/0012_groupbuy.sql`).
- `sellers`(계좌 포함)는 service_role 전용. 회차는 승인된 것의 공개 필드만 anon 조회 가능 — 수수료율·정산액·메모는 컬럼 권한으로 차단.
- 셀러 포털은 자기 회차만 조회. 주문자 이름은 마스킹(김*연), 주소·연락처는 미노출.
- 트래킹(Meta/네이버)은 일반 구매와 동일하게 발화 — 회차 구분값 추가는 후속 작업 (§9).

## 8. 로컬 데모

`SUPABASE_SERVICE_ROLE_KEY`가 없는 개발 환경에서만 `@demo` 회차와 데모 데이터가 활성화된다 (`web/src/lib/groupbuy-demo.ts` · `groupbuyDemoMode()`). 프로덕션에서는 코드 경로 자체가 비활성. 화면에 노란 "로컬 데모" 배너가 뜬다.
